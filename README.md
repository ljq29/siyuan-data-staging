# 数据暂存

思源文档块插件：把文件或文件夹拖入“数据暂存”块，通过思源工作空间和同步机制在各设备间传递文件。

## 要求

- 思源 `3.8.10` 或更高版本（依赖 `NodeCustomBlock`）
- 每个需要使用暂存块的设备都要安装并启用本插件
- 单文件最大 `100 MiB`
- 文件夹 ZIP 下载的内容总量最大 `512 MiB`

## 安装

从 [GitHub Releases](https://github.com/ljq29/siyuan-data-staging/releases/latest) 下载 `data-staging.zip`，将其中的 `data-staging` 目录解压到当前工作空间的 `data/plugins/`，然后重新加载思源并在插件设置中启用“数据暂存”。

本地执行 `pnpm run package` 后，也可以直接把本目录中的 `plugin.json`、`index.js`、`index.css` 和 `README.md` 放入 `data/plugins/data-staging/`。

## 使用

1. 在文档中输入 `/数据暂存` 并选择带图标的命令。
2. 默认以图标网格展示，也可以切换为列表视图。
3. 将文件或文件夹拖到文件展示区域，或点击“添加文件”“添加文件夹”。拖入时展示区域会高亮；拖入文件夹时保留其中的文件层级，空目录可能被工作空间清理。
4. 点击“新建文件夹”创建目录，点击文件夹图标进入目录，使用顶部面包屑返回。
5. 也可以把文件或文件夹直接拖到某个文件夹卡片上，将其上传到该目录。
6. 点击重命名图标修改显示名称。重命名只修改名义名称，不改变实际存储路径；下载时使用显示名称。
7. 文件可直接下载；文件夹和当前目录会打包为 ZIP 下载，ZIP 内使用显示名称并保留目录结构。
8. 同名文件确认后才会覆盖。删除文件夹会同时删除其中全部内容，操作前需要确认。
9. 使用“刷新”读取其他设备同步过来的变化。

每个块对应一个独立目录：`工作空间/data/staging/<块ID>/`。目录扫描结果是文件和文件夹的事实来源；根目录下的 `.data-staging.json` 只保存显示名映射，不会显示在文件列表中。

删除文档中的暂存块**不会自动删除**对应目录和文件，以防误删。不再需要时可在块内逐个删除，或在确认块 ID 后手动清理目录。

## 同步与限制

- 文件写入后由思源原有同步机制处理，请确保工作空间已启用同步。
- 插件不建立历史版本，但思源同步自身仍可能保留云端快照。
- 两台设备同时修改同名文件时，最终内容取决于同步结果；不要在多设备上同时编辑同一个暂存文件。
- 通用文件接口会将文件读入内存，因此单文件限制为 `100 MiB`，不适合大型网盘用途。
- ZIP 在浏览器内生成，内容总量限制为 `512 MiB`，下载大目录时会占用相应内存。
- 桌面浏览器支持递归拖入目录；移动端目录选择和拖拽能力取决于浏览器，建议使用文件选择。
- 未安装插件的设备只能看到自定义块的原始内容，文件本身不会丢失。

## 开发与验证

```sh
pnpm install
pnpm run typecheck
pnpm test
pnpm run package
```

打包结果位于 `dist/data-staging/` 和 `dist/data-staging.zip`。

远程文件 API 冒烟测试需要显式提供测试实例，不会把凭据写入项目：

```sh
SIYUAN_BASE_URL=https://example.com SIYUAN_TOKEN=your-token pnpm run test:api
```

该测试只使用固定测试块 ID 对应的暂存目录，覆盖上传、中文文件名、同名覆盖、嵌套目录、空目录、下载和递归删除，并在结束时清理测试文件。

## 发布

同步修改 `plugin.json` 和 `package.json` 中的版本号，提交并推送到 `main`，然后推送对应的版本标签：

```sh
git tag v0.2.1
git push origin v0.2.1
```

GitHub Actions 会自动安装依赖、执行类型检查和测试、生成 ZIP。标签必须与两个清单中的版本一致；验证通过后，Workflow 会创建对应的 GitHub Release 并上传 `data-staging.zip`。主分支推送和手动触发只构建及上传工作流产物，不创建 Release。
